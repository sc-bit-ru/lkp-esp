# ЛК ЕСП → CRM

Расширение для Chrome. Оно копирует JSON, который страница личного кабинета уже получила, и отправляет копию на приём. Адрес кабинета и адрес приёма задаются в настройках, в коде они не зашиты.

Расширение не входит в кабинет, не хранит пароль и не обходит страницы само. Если приём недоступен, снимок остаётся в очереди браузера. Запрос в кабинет из-за этого не повторяется.

## Установка

Нужен Google Chrome 111 или новее.

Из магазина: карточка «ЛК ЕСП → CRM». Пока карточки нет, загрузите папку распакованной: `chrome://extensions`, режим разработчика, «Загрузить распакованное».

Откройте параметры расширения и заполните три поля:

1. Домен кабинета. Для личного кабинета ЕСП это `lkp.ao-esp.ru`.
2. Адрес приёма. Это https-хост, который выдаёт администратор приёма. Путь после хоста не нужен.
3. Токен приёма. Он хранится только в этом браузере и в репозиторий не входит.

Кнопка «Сохранить и разрешить доступ» спрашивает у Chrome доступ ровно к этим двум адресам. Если вкладка кабинета уже открыта, обновите её один раз.

Дальше откройте в кабинете список клиентов, кассы и нужные карточки. Страница сама запросит API, расширение снимет копию удачного ответа.

Подробная инструкция: [docs/partners.md](docs/partners.md).

Политика конфиденциальности: [store/privacy-policy.md](store/privacy-policy.md).

## Чего в приёме не будет

- пароля кабинета и cookie сессии;
- заголовка `Authorization`, с которым ходит сама страница;
- тел адресов `/auth/` и полей `accessToken`, `refreshToken`;
- ответов не `2xx`;
- страниц любого хоста, кроме домена из настроек.

Токен в консоль и в журнал не пишется. В консоли вкладки кабинета строки расширения начинаются с `[ЕСП→CRM]`.

## Сборка и проверка

```
node --test test/*.test.js
powershell -File scripts/pack-chrome-store.ps1
```
