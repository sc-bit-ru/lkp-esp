# Публикация в Chrome Web Store

Пакет для загрузки: `powershell -File scripts/pack-chrome-store.ps1`. Архив появляется в `dist/lkp-esp-<версия>.zip`. Внутри только файлы расширения, без тестов и этих документов.

Перед отправкой на проверку опубликуйте текст из `store/privacy-policy.md` по публичному https-адресу и вставьте этот адрес в форму. Приватный GitHub для этого не подходит.

## Карточка

- Название: `ЛК ЕСП → CRM`
- Краткое описание (до 132 символов): `Пересылает на указанный приём JSON, который страница кабинета уже получила.`
- Категория: Productivity
- Язык карточки: русский
- Подробное описание: текст ниже
- Политика конфиденциальности: публичный URL файла `store/privacy-policy.md`
- Один сценарий: пользователь указывает домен кабинета и адрес приёма, затем само расширение копирует JSON открытых им страниц и отправляет его на этот приём.

Иконки уже в `icons/`: 16, 48 и 128. Для витрины нужен хотя бы один снимок интерфейса 1280×800 или 640×400. Снимите страницу настроек после заполнения полей и окно расширения на открытом кабинете. Рекламный тайл 440×280 Chrome просит отдельно.

## Подробное описание

Расширение для тех, кто сам работает в личном кабинете и хочет отдать уже загруженные JSON-ответы на свой приём.

В настройках явно указываются домен кабинета и https-адрес приёма. Chrome спрашивает доступ только к этим двум адресам. Токен приёма хранится в браузере.

Расширение не логинится в кабинет, не хранит пароль и не листает списки само. Оно копирует ответы fetch и XMLHttpRequest, которые запросила открытая страница. Если приём недоступен, снимок ждёт в очереди браузера. Запрос в кабинет из-за этого не повторяется.

Не отправляются cookie, заголовок авторизации страницы, ответы /auth/ и тела с токенами доступа.

Подробная инструкция для партнёра: docs/partners.md в репозитории расширения.

## Обоснование разрешений

Писать по-английски, форма проверки на английском.

`storage` — Stores the cabinet hostname, receiver origin, bearer token, and the outbound queue on the device.

`alarms` — Retries delivery to the user-configured receiver when it is temporarily unavailable. It does not contact the cabinet.

`scripting` — Registers a content script only on the cabinet origin the user approved, to copy fetch and XMLHttpRequest responses that the page itself already requested.

`optional_host_permissions` `https://*/*` — The cabinet host and the receiver origin are typed by the user. On save the extension requests permission only for those two https origins. It does not read other sites.

Host permission is not granted at install.

## Данные в форме Privacy

- Собирает ли данные: да.
- Содержимое сайтов: JSON-ответы кабинета, который указал пользователь. Уходят только на адрес приёма, который он указал.
- Данные для входа: токен приёма, который пользователь вставил сам. Хранится локально и отправляется только на этот адрес.
- Не используются для рекламы, не продаются, не уходят третьим лицам помимо указанного приёма.
- Сертификация: данные не продаются.

## Проверка перед отправкой

1. `node --test test/*.test.js`
2. Собрать zip скриптом выше и загрузить его в dashboard, не распакованную папку с `docs/` и `test/`.
3. В тестовом профиле Chrome поставить пакет, вписать домен и приём, убедиться, что окно разрешений называет только эти два хоста.
4. Обновить вкладку кабинета, открыть список и карточку, в консоли увидеть `копия` и `CRM приняла`.
