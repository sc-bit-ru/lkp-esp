# ЛК ЕСП → CRM. Инструкция для партнёра

Расширение для Chrome. Человек сам открывает личный кабинет ЕСП, а расширение забирает JSON, который страница уже получила, и отдаёт его на приём. Приём — это сервер вашей организации или CRM, адрес которого вы вписали в настройках.

Расширение не заменяет человека в кабинете. Оно не знает пароль, не логинится, не листает списки само и не нажимает кнопки.

## Что установить

Нужен Google Chrome 111 или новее.

Из магазина Chrome: откройте карточку «ЛК ЕСП → CRM» и нажмите «Установить». После публикации ссылка будет в кабинете разработчика Chrome Web Store. Пока карточки нет, расширение можно загрузить распакованным: `chrome://extensions`, режим разработчика, «Загрузить распакованное».

После установки нажмите значок расширения и откройте «Настройки домена и приёма». Туда же ведёт пункт «Сведения о расширении» → «Параметры расширения».

## Настройки

Три поля. Пока они не сохранены, расширение молчит: ни кабинет, ни приём оно не открывает.

| Поле | Что писать |
|---|---|
| Домен кабинета | Только имя хоста. Для личного кабинета ЕСП это `lkp.ao-esp.ru`. Можно вставить адрес страницы целиком, расширение возьмёт хост. |
| Адрес приёма | `https://` и хост сервера, который принимает снимки. Адрес выдаёт администратор приёма. Путь после хоста не нужен. |
| Токен приёма | Секрет, который выдаёт администратор приёма. Приставку `Bearer` можно оставить, расширение её снимет. |

Кнопка «Сохранить и разрешить доступ» вызывает окно Chrome. В нём два сайта: домен кабинета и адрес приёма. Разрешите оба. Это единственный момент, когда расширение получает право видеть страницы кабинета и звать приём. Другие сайты оно не просит.

Токен лежит в `chrome.storage.local` на этом компьютере. В репозиторий, в письмо и на страницу кабинета его класть не нужно. Кнопка «Удалить токен» стирает его из браузера. Домен и адрес приёма при этом остаются.

Если кабинет уже был открыт, обновите вкладку один раз. Иначе перехват не увидит запросы, которые страница сделала до установки.

Сменить домен можно в тех же настройках. Старое разрешение Chrome снимается, новое спрашивается заново. Вкладку кабинета после этого тоже обновите.

## Как собрать данные

Войдите в кабинет как обычно, своим паролем. Дальше просто откройте экраны. Страница сама запросит API, расширение снимет копию удачного JSON.

Имеет смысл пройти так:

1. Список клиентов партнёра. Уходит страница `aggregated_by_inn`. Если список листается, каждая страница, которую догрузил интерфейс, тоже уходит.
2. Кассы нужного клиента. Уходит страница `cashdesks` с ИНН.
3. Карточка кассы с блоком ЕСМ: отчёт компонентов, счётчики и даты проверки марок.
4. Список заявок и карточка заявки. Email и телефон клиента есть в карточке, не в строке списка.

Кнопки «синхронизировать всё» нет. Расширение не умеет само обойти кабинет.

## Что уходит на приём

Один запрос — пачка до 20 снимков. Один снимок до 1,5 МБ. Берутся только ответы `2xx` с хоста, который записан в настройках, и только по списку путей ниже.

```json
{
  "source": "extension",
  "extension_version": "0.2.0",
  "captures": [
    {
      "url": "https://lkp.ao-esp.ru/api/v1/cashdesk/partner/cashdesks?inn=0000000000&limit=100&offset=0",
      "method": "GET",
      "status": 200,
      "page_url": "https://lkp.ao-esp.ru/...",
      "captured_at": "2026-10-24T14:30:00+07:00",
      "body": {}
    }
  ]
}
```

`body` — это тело ответа страницы, не тело запроса. Заголовок запроса страницы, cookie и `Authorization` кабинета в пачку не входят.

Одинаковый снимок расширение второй раз в очередь не ставит. Как сервер приёма обрабатывает повтор, решает сам приём.

Если приём временно недоступен, снимок остаётся в очереди браузера и уходит позже, примерно раз в минуту. Запрос в кабинет из-за этого не повторяется.

## Какие ответы пересылаются

Пока приём не прислал свой список, действует встроенный список из восьми путей. После успешного запроса списка приём может его заменить. В окне расширения написано, какой список сейчас активен.

| Когда человек это открыл | Путь |
|---|---|
| Список клиентов | `GET /api/v1/cashdesk/partner/aggregated_by_inn` |
| Кассы клиента | `GET /api/v1/cashdesk/partner/cashdesks?inn=` |
| Шапка счётчиков | `GET /api/v1/cashdesk/partner/counters` |
| Блок ЕСМ | `GET /api/v1/stats/history/cashdesk/last_component_report?cashdeskId=` |
| Марки, счётчики | `GET /api/v1/stats/history/cashdesk/scan-counts?cashdeskId=` |
| Марки, даты | `GET /api/v1/stats/history/cashdesk/mark-check-dates?cashdeskId=` |
| Список заявок | `GET /crm/api/tasks` |
| Карточка заявки | `GET /crm/api/tasks/{id}` |

Другие JSON кабинета в приём не уходят. Их путь виден в окне расширения, без тела. Финансы и выгрузка xlsx в этот список не входят.

Ответы `/auth/`, страницы другого хоста и тела с `accessToken` или `refreshToken` выбрасываются до отправки.

## Окно расширения

Значок показывает, есть ли очередь. В окне:

- домен и приём, и есть ли у Chrome доступ к ним;
- сколько снимков ждут отправки;
- время последней удачной отправки;
- текст последней ошибки приёма;
- пути JSON, которые страница получила, но которые в список не входят.

## Консоль

На вкладке кабинета откройте DevTools и отфильтруйте `ЕСП→CRM`. Типичная цепочка:

- `перехват включён, жду домен из настроек`
- `домен кабинета: lkp.ao-esp.ru, путей 8`
- `копия GET /api/v1/... · HTTP 200`
- `в очереди`
- `отправляю в приём 1`
- `CRM приняла 1`

`auth не отправляю` значит, что ответ входа отброшен. `другой JSON, в CRM не шлю` значит, что путь только показан локально. `CRM недоступна, снимок остаётся в очереди` значит, что повтор будет в приём, не в кабинет.

Тело JSON и токен в эти строки не пишутся.

## Свой приём

Сервер приёма должен отвечать по HTTPS и принимать три маршрута с заголовком `Authorization: Bearer <токен>`.

`POST /api/v2/ingest/esp-lkp/capture` — пачка из примера выше. Ответ:

```json
{ "ok": true, "accepted": 1, "ignored": 0, "results": [ { "kind": "cashdesks" } ] }
```

`ignored` значит «увидели и не писали»: чужой путь, авторизация, секрет. `ok: false` у одного снимка не отменяет остальные. Расширение считает пачку принятой, если HTTP `2xx` и общий `ok` не `false`.

`GET /api/v2/ingest/esp-lkp/spec` — список путей. Подойдёт массив строк `GET /путь?параметр=` или объекты `{ "method": "GET", "path": "/путь", "query": ["inn"] }`. Поле может называться `paths`, `routes`, `endpoints`, `rules` или `items`. Если список не разобран, остаётся встроенные восемь путей.

`GET /api/v2/ingest/esp-lkp/status` — когда был последний снимок. Расширение показывает в окне первое найденное поле времени: `last_capture_at`, `lastCaptureAt`, `last_snapshot_at`, `captured_at`, `last_at`.

Без токена эти адреса отвечают `401`. Редирект на другой хост расширение не проходит, чтобы токен не уехал вслед за ним.

## Чего в приёме не будет

- пароля кабинета и cookie сессии;
- заголовка `Authorization`, с которым ходит сама страница кабинета;
- тел `/auth/`, `accessToken`, `refreshToken`;
- ответов не `2xx`;
- страниц любого хоста, кроме домена из настроек;
- файлов Excel и прочих путей вне списка.

## Если данные не приходят

1. В настройках сохранены домен, приём и токен, Chrome показал, что доступ разрешён.
2. Вкладка кабинета обновлена после сохранения.
3. В консоли есть строка `копия`. Если её нет, страница ещё не запросила API: откройте список или карточку.
4. Если копия есть, а `CRM приняла` нет, смотрите текст ошибки в окне расширения. `401` — токен. Сеть и `5xx` — снимок подождёт в очереди.
5. Путь из консоли со словами `другой JSON` в текущий список не входит. Его добавит администратор приёма в `spec`.

Токен заново выдаёт администратор приёма. Расширение само пароль кабинета не восстанавливает.
